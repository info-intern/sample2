# Webアプリ開発依頼テンプレート

以下の仕様に基づいて、スマートフォン(iPhone)で動作するWebアプリを開発してください。

---

## 1. アプリの目的

- **誰が使う**: 
  幼稚園の先生（通園バスに同乗する先生・クラス担任）。
  園児は、カメレオンコードを印刷した名札を帽子やカバンに付けている。

- **何のために使う**: 
  通園バスへの園児の置き去り事故を防ぐため。
  バスの乗車・降車や登園・降園のたびに名札のコードを読み取り、
  「今どの子がどこにいるのか」「バスに乗ったのに降りていない子はいないか」を
  先生がひと目で確認できるようにする。

---

## 2. 主な機能

- 全園児の「今の状態」（未登園／バス車内／園内／帰宅済み／欠席）を一覧で確認できる
- 点呼の種類（バス乗車・バス降車・登園・降園）を選んで点呼を開始し、名札のコードを読み取ると、確認済みの園児が画面に積み上がっていく
  - 1回の読み取りで、カメラに映った複数の名札をまとめて読み取れる
  - 読み取りは何度でも繰り返せ、読み取るたびに確認済みの園児が追加されていく
- 点呼中は「確認済み」と「まだ確認できていない子」を並べて表示し、残り人数がすぐわかる
- バス降車の点呼を確定したとき、乗車したのに降車で確認できていない子がいれば、赤く大きな警告を表示する
- バス車内に残っている子がいる間は、一覧画面の上部にも警告を出し続ける
- 保護者から欠席の連絡があった園児について、欠席理由・体温・メモを入力できる
- その日の点呼の記録を時系列で確認できる
- 記録はアプリを閉じたり再読み込みしたりしても消えずに残る

---

## 3. 画面構成・操作フロー

### 画面一覧

| 画面名 | 概要 |
|---|---|
| ホーム画面（在籍一覧） | 全園児を状態ごとに色分けして一覧表示する。クラスで絞り込める。状態ごとの人数（例: 園内 8人／バス車内 2人）を表示する。バス車内に子が残っていれば上部に警告を表示する |
| 点呼開始画面 | 点呼の種類（バス乗車・バス降車・登園・降園）と、バス乗車／降車の場合はバスのコースを選ぶ |
| 点呼中画面 | 「読み取る」ボタンでリーダーを起動し、読み取りを終えて戻るたびに確認済みの園児が積み上がっていく。「確認済み ○人」「未確認 △人」と、未確認の子の名前を表示する。「確定」ボタンで点呼を終える |
| 置き去り警告画面 | バス降車の点呼を確定したとき、未確認の子がいれば表示する。該当する子の名前を赤く大きく表示し、「すぐに車内を確認してください」と案内する。見つかった子は、その場でコードを読み取るか「発見済み」ボタンで園内に変更できる |
| 欠席連絡画面 | 園児を選び、欠席理由・体温・メモを入力して保存する |
| 点呼履歴画面 | その日の点呼記録を時系列で表示する（いつ・どの点呼で・何人確認したか・未確認者は誰か） |

### 操作の流れ

```
起動
  → ホーム画面（全員の状態を確認。必要なら「欠席連絡」から欠席を登録）
  → 点呼開始画面（「バス乗車」と「Aコース」を選んで開始）
  → 点呼中画面（「読み取る」で乗ってくる子の名札を読み取る → 完了で戻る → 全員そろうまで繰り返し → 「確定」）
  → ホーム画面（Aコースの子が「バス車内」になる）
  → 点呼開始画面（園に着いたら「バス降車」と「Aコース」を選んで開始）
  → 点呼中画面（降りてきた子を並ばせ、名札をまとめて読み取る → 「確定」）
  → （未確認の子がいれば）置き去り警告画面（車内を確認し、見つけた子を確認済みにする）
  → ホーム画面（全員「園内」になったことを確認）
```

### 点呼の種類と対象

| 点呼の種類 | 点呼の対象になる園児 | 確定後の状態 |
|---|---|---|
| バス乗車 | 選んだコースの園児のうち「未登園」の子（欠席を除く） | バス車内 |
| バス降車 | 選んだコースの園児のうち「バス車内」の子 | 園内 |
| 登園 | 「未登園」の子（欠席を除く） | 園内 |
| 降園 | 「園内」の子 | 帰宅済み |

## 4. デザイン仕様

- **アクセントカラー**: 明るいオレンジ系（幼稚園らしい親しみやすさ）
- **雰囲気**: やさしく親しみやすいが、警告は誰が見てもすぐわかるようにはっきり目立たせる
- **その他の希望**: 
  - 状態ごとの色を固定する（例: 未登園＝グレー、バス車内＝黄、園内＝緑、帰宅済み＝青、欠席＝薄いグレー）。置き去り警告だけは赤を使う
  - 園児を抱っこしながら片手で操作することを想定し、ボタンは大きめにする
  - リーダーの読み取り画面では、認識したコードの上に園児の名前を表示する
  - 読み取りから戻ったとき、今回新しく追加された園児がはっきりわかるように表示する

## 5. アプリで扱うデータ

### (1) 最初から用意しておく一覧データ

**園児名簿**（全30名＝各クラス10名。名前はすべて架空）

| クラス | ひよこ組／うさぎ組／きりん組 |
| 通園方法 | Aコース（バス）／Bコース（バス）／徒歩・送迎 |

### (2) 操作すると記録されるデータ

**園児の状態**（園児ごとに1件）

| 項目 | 説明 |
|---|---|
| コード | 園児のコード |
| 状態 | 未登園／バス車内／園内／帰宅済み／欠席 |
| 最終確認日時 | 最後に状態が変わった日時 |

**点呼記録**（点呼を確定するたびに1件）

| 項目 | 説明 |
|---|---|
| 点呼日時 | 点呼を確定した日時 |
| 点呼の種類 | バス乗車／バス降車／登園／降園 |
| コース | Aコース／Bコース（バス乗車・降車のときのみ） |
| 確認済みの園児 | 読み取れた園児のコードの一覧と、それぞれの読み取り時刻 |
| 未確認の園児 | 対象だったが読み取れなかった園児のコードの一覧 |

**欠席連絡**（欠席を登録するたびに1件）

| 項目 | 説明 |
|---|---|
| 日付 | 欠席する日 |
| コード | 欠席する園児のコード |
| 欠席理由 | 体調不良／家庭の事情／その他 から選ぶ。必須 |
| 体温 | 欠席理由が「体調不良」のときのみ入力。任意。34.0〜42.0 の数値、小数第1位まで |
| メモ | 任意、200文字以内 |
| 登録日時 | 欠席連絡を保存した日時 |

### 入力チェックのルール

- 欠席理由が未選択の場合は保存できず、メッセージで案内する
- 体温に数字以外が入力された場合や、34.0〜42.0 の範囲外の場合は保存できず、メッセージで案内する
- メモが200文字を超える場合は保存できず、残り文字数を表示して案内する
- 長いメモを入力しても、画面のレイアウトが崩れないようにする

## 補足・その他

- reference.md を参照すること
- カメレオンコードの読み取りには IroatoReader API を使う（詳細は reference.md）
  - 読み取るコードの種類はカメレオンコード（`'cc'`）、読み取りモードは複数（`IroatoReader.multi`）とする
  - リーダーの完了ボタンで戻ったとき、読み取れたコードをまとめて点呼中画面の「確認済み」に追加する
  - リーダーの読み取り画面には、`displayData` を使ってコードの代わりに園児の名前を表示する
  - リーダー下部の案内文（`labelText`）に、点呼の種類（例: 「Aコース バス降車」）を表示する
- 使用できるカメレオンコードは "1"〜"100" の100種類。今回は "1"〜"30" を園児の名札に割り当て、"31" 以降は「名簿にないコード」の確認用に使う
- 同じ園児のコードを2回以上読み取った場合（1回の読み取りの中での重複、別の回の読み取りとの重複のどちらも）は、重複して追加しない。別の回で読み取り済みだった子は「すでに確認済みです」と表示する
- 名簿にないコードを読み取った場合は「登録されていないコードです（コード: ○）」と表示する
- 点呼の対象外の園児（例: 欠席連絡がある子、別のコースの子）を読み取った場合は「対象外の園児です」と表示し、それでも確認済みに追加するかを先生に選ばせる（複数いる場合は1人ずつ確認する）
- 園児名簿の初期データは JSON ファイルで用意する
- 点呼中画面で「確定」を押したとき、未確認の子がいる場合は「未確認の子が○人います。確定しますか？」と確認する（バス降車の場合は、確定後に置き去り警告画面へ進む）
- 日付が変わったら、全園児の状態を「未登園」に戻す（過去の点呼記録は残す）
- 動作確認・デモ用に、ホーム画面の下部に「データをリセット」ボタンを置く（押すと確認メッセージを表示してから全データを消去する）
- データは使用している iPhone の中だけに保存される。複数の先生の端末で記録を共有することはできない（1台の iPhone で運用する前提）
- 帰りのバス（降園後のバス乗車・降車）の管理は今回の対象外とする
- **このアプリはインターン学習用のサンプルであり、実際の園児の安全管理に使用できるものではない。** 園児名・クラス名などのデータはすべて架空のもの
